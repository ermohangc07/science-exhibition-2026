# Team Roles (3 members per project)

Don't lock these in as permanent titles — rotate roles partway through so everyone touches every part.

1. **Builder / Circuit Lead** — wiring, hardware assembly, sensor calibration (or, for software projects, setting up the environment and running the code).
2. **Coder Lead** — writes and debugs the logic.
3. **Test & Documentation Lead** — tracks what works/fails in a build log, preps the presentation poster/slide.

## Build log format

Keep this simple — a few lines per day is enough:

```
Day 2:
- Tried: connecting the moisture sensor directly to 5V
- Failed because: readings were always maxed out
- Fixed by: adding a voltage divider / switching to A0 analog pin
```

This log is what makes your "failure and fix" story for the judges — it's often the most impressive part of the presentation, more than the finished project itself.

## Presentation checklist

- [ ] 30-second problem statement ready
- [ ] Can explain how it works in plain language (no jargon dump)
- [ ] Have one specific failure-and-fix story ready to tell
- [ ] Backup video/photos in case live demo fails
- [ ] Poster/slide includes: circuit diagram or flowchart, code snippet, build photos
