# 7-Day Roadmap

Every team follows this same schedule, regardless of project. Check off each day before moving to the next.

## Day 1 — Assign, brief, wire basics
- Read your project's README fully.
- Hardware teams: connect components, confirm power turns on.
- Software teams: run the starter code, confirm it opens/runs without errors.
- **Goal:** something turns on / opens. Nothing more yet.

## Day 2 — Core mechanic working
- Get the ONE core behavior working (e.g. button → buzzer, bird falls with gravity, one shape draws).
- Don't add extra features yet — a working core is more valuable than a half-built full feature.

## Day 3 — Full logic complete
- Extend the core into the complete feature described in your README.
- It's okay if it's rough — full and ugly beats partial and polished at this stage.

## Day 4 — Integration + edge cases
- Test your project 10+ times in a row.
- Write down every time it breaks and why — this becomes your "problem we solved" story.
- Fix what you can; note what you couldn't fix and why.

## Day 5 — Polish
- Hardware teams: build a simple enclosure/housing.
- Software teams: add score display, colors, clean up messages.
- No new core features today — polish only.

## Day 6 — Full dry-run + poster
- Run your complete demo twice, timed.
- Prepare your poster/slide: problem statement, how it works, one failure-and-fix story.
- Prepare a Plan B (backup video or photos) in case the live demo fails.

## Day 7 — Final rehearsal
- One last full run-through under exhibition-like conditions.
- Charge batteries, pack spare parts.
- Keep this day light — avoid big last-minute changes.
